## Verdict: **changes required**

The core is solid and well tested:
- The run state machine is fenced by the generation. Every step write goes through `StepContext.tx`, which locks the row and checks the generation and `running`. `_fail` and `_cancel` are fenced too, and the ledger refuses a stale generation.
- The ids are uuid5, so resumed steps skip work that is already persisted. The resume tests cover a kill in every step, both mid-step and at the boundary, plus Hypothesis sequences of kills.
- The code checks every citation before the Critic sees it. The show rule counts distinct `(source_type, ref)` pairs on verified rationale and objection claims, needs at least one literature item and a measured count, and the domain re-checks it on every read. `visible_claims` filters claims and evidence.
- OpenAlex calls are counted before they are made, and the cap holds under concurrency.
- Database errors reach `last_error`, logs and spans only as class, SQLSTATE and constraint. Check (a) confirms this.
- Every endpoint is owner-scoped and answers 404 for anything else.

Two findings block approval:
1. A model quote of 301 to 600 characters makes `analyse` crash on PostgreSQL. The claims are never persisted and the run fails after five paid retries. Reproduced in (a).
2. The new read and command service (`DiscoveryService`: cancel, status, evidence open, admin claims with vault-quote redaction) has no unit tests against fakes. The admin redaction privacy rule has no test at all. This is a DoD item.
