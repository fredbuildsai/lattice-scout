## Verdict: **changes required**

**What works:**
- **The evidence-shown rule holds end to end.** The frontend only renders what the API returns. The API passes everything through `show_decision` and `visible_claims`: `service.py:269`, `:309`, `:381-385`. So cards, the detail page, the Home briefing and the popovers carry only verified claims with verified markers. Unverified claims never reach a DTO.
- **No sensitive data in analytics.** Events carry ids, counts and source types only. A vault quote reaches the UI only as the verified quote of at most 300 characters. A passage is shown only under `keep`. Under `discard`, the UI shows "Original file not kept".
- **The feedback backend is clean.** It is a hexagonal context with a fake, unit tests, a PostgreSQL test of the view, and an API test with an intruder account. Its rows are erased with the account (`test_account_erasure_pg.py:212`).

**Two items block approval. Both are Definition of Done items:**
1. No Playwright test covers the M4 main path, and nothing checks W4, W5 or W6 at 390 px. Acceptance criterion 1 is therefore shown only in pieces.
2. The user notes and module docs were not updated for the new features.
