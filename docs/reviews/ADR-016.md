## Verdict: **changes required**

**What works:**
- **The mechanism is sound and fails closed.** `AgentInput` rejects an unclassified field when the class is defined. An item with no `is_confidential` counts as confidential. An `AgentSpec` without a class, or a prompt with no `data_class`, defaults to confidential. `InsightExtractor` and `InsightTopicTagger` have no published form. `AgentFactory.run` applies `input_for_route` to every call, so no builder can forget it.
- **Pinning is real.** `build_router_config` builds `<route>__confidential` routes from authorized members only. `route_for` refuses a confidential call that has no pinned route. `MeteringCompletion.check_model` runs in the same thread before every provider request. I confirmed in `llmrouter_free/router.py` that `complete()` calls `completion_fn` synchronously and only walks `self.routes[route]`. The default `config/llm_router.yaml` marks nothing, so nothing confidential leaves the process today.
- **Published-only use cases are well covered.** `test_real_agent_stack_over_a_spy_backend_never_sees_vault_strings` runs the real agent stack against a spy backend. Matching has tests for both profile and joint ideas. Ingestion parks documents and the sweep requeues them only when a provider is ready. Error paths stay content-free: adapter errors are re-raised `from None`, and `confidential_refused` / `agent_skipped` logs carry no text.

**One item blocks approval:** pinning is decided by whether a *confidential-tagged field* is non-empty, not by where the content came from. Text derived from the vault sits in published-tagged fields (the Critic's draft, the vault keyword in novelty queries, earlier opportunity titles). It therefore goes over the unpinned route to any deployment. This happens in the very setup B6 asks for (some providers authorized, others not), and also after authorization is withdrawn. ADR §1 ("anything derived from them") and the UI promise ("never to any other provider") are both broken.
