## Verdict: **changes required**

**What works:**
- **The double opt-in rule holds in three independent layers.** (1) `match_reveal_v` has `WHERE mp.state = 'mutual'` and drops deleted accounts. (2) A composite foreign key means `joint_idea` can exist only for a mutual match, and a mutual match with ideas cannot change state. (3) `build_revealed` raises before mutual. PostgreSQL tests cover every non-mutual state (`test_matching_reveal_pg.py:150-154`, `:232-240`). At HEAD, `SqlRevealRepo.contact` is the only code that reads identity for a match. No other adapter, view or e-mail template joins `researcher` or `account` to a proposal; the M6 notification mails carry only a link.
- **Decline secrecy is a tested property, not just a promise.** `status_for` never reads the other side's decision. `_decide_after_decline` answers exactly as if the other side had done nothing. There is no decline event and no decline notifier method. Hypothesis checks the cut history (I3, `test_reveal_properties.py:155`) and checks that A never sees B's yes (I4). The DTOs have no field for `declined_by`, `close_reason` or the other side's decision.
- **The anonymous card is lean.** It shows the field, a continent, a career band, at most 5 shared OpenAlex topic names, method texts, `why`, score and dates. The explainer gets no works, names, institutions, years or countries. `they_bring` has no refs. The template fallback uses only vocabulary labels. The F-37 copy is fixed (`MatchesPage.tsx:33-35`).

**One item blocks approval (acceptance 1 and the DoD).** The main path is never run end to end: not on PostgreSQL through the API, and not in Playwright.
