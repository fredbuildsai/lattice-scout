## Verdict: **changes required**

**What works:**
- **The erasure scan is the real thing.** `test_account_erasure_pg.py` walks every base table in every schema and every non-bytea column, with no allow-list. A coverage guard fails when a table has no needle row (slice D extended the seed for `notification` and `notification_pref`). An FK guard checks that every FK to the user roots is CASCADE or SET NULL. The test goes through the real API and worker, runs both passes and also lists the bucket. It caught a real bug during the build (`MatchRepo.save` did not write `rationale`).
- **The job is careful with its own traces.** The payload key is `subject_id`, so the worker does not take it as `account_id` context. Dedupe keys are hashed. The payload is rewritten in the finish transaction. The tombstone holds only an HMAC and the counts. Cost rows are made anonymous, not deleted. Stale tokens are refused through the tombstone index.
- **Mails give nothing away.** The four templates are fixed text plus a link, with no names, counts or decisions. There is no decline mail. The digest has no counts (DECISIONS 98, F-43). The recipient query skips deleted accounts. The console sender logs only the domain.
- **Hardening is broad and tested:** RLS on every table and partition (with a guard test), strict CORS with prod refusal of `*` and `http://`, a pure-ASGI header middleware, `/docs` off in prod, a route walk that fails on any unauthenticated route that is not listed, a static trace-redaction guard, 13-month partition retention, and analytics opt-out on both client and server.

**Two items block approval:** (1) the LLM provider switch sends vault text to free-tier endpoints, which goes against the no-training rule; (2) the DoD Playwright smoke test for the milestone is missing.

## Known items F-43 to F-48, re-judged

- **F-43** (digest has no counts): agree, low. This is the right choice for decline secrecy.
- **F-44** (magic-link branding is set in the Supabase dashboard): agree; it is a human step, not a code gap.
- **F-45** (race on `account_email_key` at first login): raise to **should-fix before the pilot**. It is a real race, not only a flaky test: two parallel first requests (the SPA sends several on load) can return 409 `EmailInUse` to a legitimate new user. Map that unique violation to a re-read.
- **F-46** (live eval stub): acceptable while paid calls are a hard stop. The workflow itself is stale (#12).
- **F-47** (no per-IP rate limit on `/events` and sign-in): agree, medium. It must be in place, at the proxy or as middleware, before any public URL exists.
- **F-48** (`analytics_opt_out` stored in `notification_pref`): agree, low (a placement nit).
