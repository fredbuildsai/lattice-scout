## Verdict: **changes required**

Most of the core is careful and well tested. The state machine is strict. Ingestion is resumable and never holds a transaction during storage, extraction or LLM calls. Under `discard`, chunk text is redacted in the same commit as every terminal transition (`ready`, `failed`, `rejected`, and `fail_document` from the sweeper). Purge is idempotent with one audit row. Deletion empties chunks and insights at commit and uses the `deleting` row as the outbox. Owner isolation answers 404 everywhere and is tested on Postgres. Storage keys never contain the filename, and `validate_key` blocks traversal. The factory re-raises `from None` with fixed messages. Parsing runs in a child with `RLIMIT_AS`/`RLIMIT_CPU`, a wall-clock kill and `stderr` sent to `/dev/null`.

Two privacy findings block approval:

1. Vault-derived text reaches `job.last_error`, the `job_failed` log and the OTLP job span through a Postgres error message. This is reproduced. It breaks invariant 9.
2. Under `discard`, `document_insights.payload` keeps verbatim document text of any length, and the API returns it. This is reproduced. It breaks DECISIONS 42, design invariant 2 and the user guide's "short quotes … up to 300 characters".
