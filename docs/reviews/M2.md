## Verdict: **changes required**

Most of the core is careful and well tested. The state machine is strict. Ingestion is resumable and never holds a transaction during storage, extraction or LLM calls. Under `discard`, chunk text is redacted in the same commit as every terminal transition (`ready`, `failed`, `rejected`, and `fail_document` from the sweeper). Purge is idempotent with one audit row. Deletion empties chunks and insights at commit and uses the `deleting` row as the outbox. Owner isolation answers 404 everywhere and is tested on Postgres. Storage keys never contain the filename, and `validate_key` blocks traversal. The factory re-raises `from None` with fixed messages. Parsing runs in a child with `RLIMIT_AS`/`RLIMIT_CPU`, a wall-clock kill and `stderr` sent to `/dev/null`.

Two privacy findings block approval:

1. Vault-derived text reaches `job.last_error`, the `job_failed` log and the OTLP job span through a Postgres error message. This is reproduced. It breaks invariant 9.
2. Under `discard`, `document_insights.payload` keeps verbatim document text of any length, and the API returns it. This is reproduced. It breaks DECISIONS 42, design invariant 2 and the user guide's "short quotes … up to 300 characters".

### Verdict: **approve**

Both round-1 blockers are fixed for the paths that were reproduced, and mutation tests confirm each fix:
- NUL in model output no longer fails the job or leaks. `_clean` strips control characters, and removing it turns `test_nul_in_model_output_does_not_fail_the_job_or_leak` red.
- `describe_exception` keeps only the class, SQLSTATE and constraint name for database errors. Removing that branch turns `test_database_error_descriptions_never_quote_row_or_json_text` red.
- Under `discard`, items are bounded to 300 characters, and quotes longer than 300 characters are unverified. Removing either fix turns `test_discard_never_keeps_more_than_300_characters_of_verbatim_text_anywhere` red.
- The upload body is no longer read before authentication or past a declared over-limit `Content-Length`. Removing that check turns `test_upload_guard_refuses_before_reading_the_body` red.
- The job lease is extended by a heartbeat, covered by the queue contract test on both adapters and the worker test.
- Unverified items are now checked at the API on Postgres. Removing `.visible()` turns `test_unverified_items_are_stored_but_never_returned` red.

None of the new findings breaks an acceptance criterion, an invariant or the DoD with a path I could reach in M2 code. N1, however, is a real mechanism by which vault text could reach traces and server logs. It should be fixed before M3 adds more SQL writes and HTTP endpoints.
