**Goal (plan M0.11):** `LLMPort` + `FakeLLM` (deterministic, schema-valid, from fixtures); `LlmRouterAdapter` over `/home/user/llmrouter-free` (D4 / decision 3); ADR-010 follow-up; every real call captures input/output/cached/reasoning tokens into `UsageMeterPort`; live tests `needs_network`.
**Goal (plan M0.12):** request context (done in M0.5), `UsageMeterPort` + `BufferedUsageMeter`, `llm_call`/`external_call` (monthly partitions), price table; `AnalyticsPort` + `BufferedAnalytics`, `app_session`/`analytics_event`, `POST /events` (202), event catalogue; OpenTelemetry; `analytics.*` views. **Acceptance:** 5 page views → 5 `page_view` rows (right `prev_page`, `dwell_ms`, one `session_id`), visible in `v_page_transitions`; a test agent call through `LLMPort` writes an `llm_call` row with tokens and cost (FakeLLM is enough offline); `POST /events` p95 < 20 ms and API p95 within 5 % with analytics on vs off.

## 1. ADR-010 follow-up (decision 13)
**Direct structured-output calls, not a custom Agents SDK model provider.** llm-router is sync, chat-completions via LiteLLM, and returns text + parsed output. It does not pass tool calls through or stream. A custom `agents.Model` would mean rebuilding the SDK's tool loop on top of it. So `LlmRouterAdapter` sends `[system=instructions, user=input JSON]` with `validate=json_validator(output_type)` and `response_format=json_schema_response_format(output_type)` (or `json_mode=True` when `spec.strict_schema` is False). Agent "tools" (`lookup_work`, `search_similar`, §6.4) become **pre-fetched context in the input**: the run corpus is already stored, and evidence is verified in code anyway. The Agents SDK is only used by the D4 fallback `OpenAIAgentsDirectAdapter`.

## 2. Ports (`scout/ports/`, stdlib + pydantic + `scout.shared` only)
**`llm.py`**
- `ModelTier(StrEnum)`: `fast`, `reasoning`.
- `@dataclass(frozen=True) AgentSpec(Generic[OutT])`, `OutT` bound to `BaseModel`: `name: str` (e.g. `"QueryPlanner"`), `prompt_version: str`, `tier: ModelTier`, `instructions: str`, `output_type: type[OutT]`, `temperature: float = 0.2`, `max_output_tokens: int = 4096`, `strict_schema: bool = True`. A dataclass because it holds a class.
- `CallContext(BaseModel, frozen)`: `feature: str`, `account_id: UUID | None`, `session_id: UUID | None`, `run_id: UUID | None`. `@classmethod from_request(ctx: RequestContext, feature: str)` parses `session_id` and maps bad values to `None`. The prompt version comes from the spec.
- `TokenUsage(BaseModel, frozen)`: `input_tokens: int`, `output_tokens: int`, `cached_input_tokens: int | None`, `reasoning_tokens: int | None` (all `ge=0`). `None` means the provider did not report it. A validator enforces cached ≤ input and reasoning ≤ output.
- `AgentResult(BaseModel, Generic[OutT], frozen)`: `output: OutT`, `model: str`, `route: str`, `usage: TokenUsage` (summed over attempts), `cost_usd: Decimal`, `latency_ms: int`, `attempts: int`. M3 adds `cost_usd` into `analysis_run`.
- `class LLMPort(Protocol): async def run(self, agent: AgentSpec[OutT], input: BaseModel | Mapping[str, JsonValue], ctx: CallContext) -> AgentResult[OutT]`.
- Errors: `LLMUnavailable(InfrastructureError)` code `llm_unavailable` (503, every deployment exhausted); `LLMOutputInvalid(InfrastructureError)` code `llm_output_invalid` (502). Codes stay unique (kernel invariant 3).

**`usage.py`**
- `LlmCallStatus(StrEnum)`: `ok, invalid_output, rate_limited, error`. `ExternalService(StrEnum)`: `openalex, email, storage`.
- `LlmCallRecord(BaseModel, frozen)`: `id: UUID`, `ts: AwareDatetime`, `account_id`, `session_id`, `run_id` (all `UUID | None`), `feature: str`, `agent: str`, `route: str`, `provider: str`, `model: str`, `attempt: int` (1-based), `input_tokens`, `output_tokens`, `cached_input_tokens: int | None`, `reasoning_tokens: int | None`, `latency_ms: int`, `cost_usd: Decimal`, `status: LlmCallStatus`, `error_type: str | None`, `prompt_version: str`, `trace_id: str | None`.
- `ExternalCallRecord`: `id`, `ts`, `account_id`, `session_id`, `run_id`, `service: ExternalService`, `endpoint: str` (a route template; no ids and no query values), `status: Literal["ok","error","timeout"]`, `http_status: int | None`, `latency_ms`, `cost_usd: Decimal = 0`, `cache_hit: bool`, `trace_id`.
- `ModelPrice(BaseModel, frozen)`: `input`, `output`, `cached_input`, `reasoning` (`Decimal`, USD per 1M tokens). `PriceTable(BaseModel, frozen)`: `version: str`, `models: dict[str, ModelPrice]`, `default: ModelPrice`. It has `price_for(model) -> tuple[ModelPrice, bool]` (exact match, then the part after the last `/`, else `(default, False)`) and `cost(model, usage) -> Decimal` = `((in - cached)*p.input + cached*p.cached_input + out*p.output) / 1e6`, quantized to `1e-8`. **Cached tokens are part of input and reasoning tokens are part of output (OpenAI semantics), so the `reasoning` price is never added on top.**
- `class UsageMeterPort(Protocol)`: `record_llm_call(rec) -> None`, `record_external_call(rec) -> None`. Both are sync, never raise, and never do I/O.

**`analytics.py`** + **`analytics_catalogue.py`**
- `AnalyticsEvent(BaseModel, frozen)`: `id: UUID`, `ts: AwareDatetime` (server time), `account_id: UUID | None`, `session_id: UUID`, `name: str`, `page: str | None`, `prev_page: str | None`, `dwell_ms: int | None`, `properties: dict[str, str | int | float | bool | None]`, `client_ts: AwareDatetime | None`, `seq: int | None`.
- `SessionTouch(BaseModel, frozen)`: `session_id`, `account_id`, `seen_at`, `user_agent_family`, `device_type` (`desktop|mobile|tablet|other`), `viewport`, `app_version`, `entry_page`, `referrer_domain` (all `str | None`).
- `class AnalyticsPort(Protocol)`: `track(evt) -> None`, `touch_session(s: SessionTouch) -> None`. Both are buffered and never raise.
- `EVENT_CATALOGUE: Mapping[str, frozenset[str]]` maps an event name to its allowed property keys: `page_view` (no properties; uses page, prev_page and dwell_ms), `web_vital{metric,value,rating}`, and every name in ARCHITECTURE §11.2, with ID or enum properties only (e.g. `opportunity_opened{opportunity_id,position}`, `match_decision{match_id,decision}`, `menu_item_clicked{item}`). `validate_event(name, props) -> str | None` returns a rejection reason: unknown name, unknown key, or a string longer than 64 characters.

## 3. Adapters
- `adapters/llm/prompts.py`: `load_agent_spec(prompts_dir, name, output_type) -> AgentSpec`. It reads the front-matter (`name`, `version`, `tier`, `output_type`) and the body as `instructions`, and raises if `output_type.__name__` does not match.
- `adapters/llm/metering.py`: `record_for(spec, ctx, attempt, model, usage, status, latency_ms, error_type, prices, clock, ids) -> LlmCallRecord`, plus `provider_of(model)` (the LiteLLM prefix before `/`, else `"openai"`) and `current_trace_id()` (OTel, `None` when the span is invalid). All three LLM adapters share these.
- **`FakeLLM(fixtures_dir: Path, usage, prices, clock, ids)`** in `adapters/llm/fake_llm.py`. Resolution order: (1) a scripted override `fake.script(agent_name, output | Callable[[input], output])` for unit tests; (2) `<dir>/<Agent>/<sha256(canonical input JSON)[:16]>.json`; (3) `<dir>/<Agent>/default.json`; (4) otherwise raise `FakeFixtureMissing`, which lists the expected paths. Each fixture goes through `output_type.model_validate`, and an invalid one raises `LLMOutputInvalid`. Synthetic usage: `input = ceil(len(instructions + input_json) / 4)`, `output = ceil(len(output_json) / 4)`, `cached = 0`, `reasoning = 0`, `model = "fake"`, `provider = "fake"`, `route = tier`, `latency_ms = 0`. It records one `llm_call` with `status=ok`. Canonical JSON uses `json.dumps(..., sort_keys=True, separators=(",", ":"))` (pydantic inputs via `model_dump(mode="json")`).
- **`LlmRouterAdapter(router, prices, usage, clock, ids, route_for: Mapping[ModelTier, str], executor)`** in `adapters/llm/llm_router.py`. Bootstrap builds `LLMRouter(load_routes(cfg), completion_fn=MeteringCompletion(), allow_paid=s.llm_router_allow_paid, max_usd_per_day=s.llm_router_max_usd_per_day)` **directly** (`build_router` has no `completion_fn` parameter). `MeteringCompletion` wraps `litellm.completion` (lazy import). For each provider attempt it appends `Attempt(model, usage from response.usage incl. prompt_tokens_details.cached_tokens / completion_tokens_details.reasoning_tokens, latency_ms, error_type)` to a `threading.local` list, then re-raises any exception. `run()` resets the list, calls `router.complete(route, msgs, validate=..., response_format=..., temperature, max_tokens, use_cache=False)` in a **dedicated `ThreadPoolExecutor(LLM_MAX_CONCURRENCY)` via `loop.run_in_executor(pool, contextvars.copy_context().run, fn)`**, and emits **one `llm_call` row per attempt**. Status per attempt: the exception class gives `rate_limited` (status_code 429) or `error`. Transport-ok attempts other than the accepted last one are `invalid_output`. If every deployment is exhausted, it records the rows first, then raises `LLMUnavailable`. llm-router's own `Deployment.cost` is ignored; our price table is the single source.
- **`OpenAIAgentsDirectAdapter(prices, usage, clock, ids, model_for: Mapping[ModelTier, str])`** (D4 fallback, `llm` extra). It builds `Agent(name, instructions, model, output_type)` and calls `Runner.run(agent, input_json, run_config=RunConfig(trace_include_sensitive_data=False, tracing_disabled=True))`. It writes one row per run from `result.context_wrapper.usage` (`input_tokens`, `output_tokens`, `input_tokens_details.cached_tokens`, `output_tokens_details.reasoning_tokens`). If this takes more than 1 h, `openai_direct` raises a config error in bootstrap and the work moves to `BACKLOG`.
- `adapters/observability/buffer.py`: `BufferedWriter[T](sink: Callable[[list[T]], Awaitable[None]], *, capacity, batch_size=500, flush_ms, sample: Callable[[T], bool] | None, name)`. It uses a `deque` with a manual bound. `offer(item)` is sync and **never raises**: it drops when full, and at ≥ 80 % full it drops items for which `sample(item)` is False. `start()` creates the loop task, which ticks every `min(flush_ms, 250)` ms and flushes when `len ≥ batch_size` or `flush_ms` has elapsed. On sink failure the batch goes back to the front (if there is room) and is retried; after 3 consecutive failures it is dropped with an error log. `close(deadline_s=5)` stops the loop and drains everything. `offer` after `close` drops the item. It counts `delivered`, `dropped`, `sampled_out` and `failures`.
- `adapters/observability/usage_meter.py`: `BufferedUsageMeter(db, flush_ms, capacity=10_000)` holds two writers (llm, external), with **no sampling**. Sinks use one SQLAlchemy Core `insert(table).values(rows)` per batch.
- `adapters/observability/analytics.py`: `BufferedAnalytics(db, flush_ms, capacity=20_000)`. Sampling keeps `page_view` always and 1 in 4 of the other events when ≥ 80 % full. Its session sink de-duplicates by id per batch, then runs `INSERT … ON CONFLICT (id) DO UPDATE SET last_seen_at = GREATEST(...), account_id = COALESCE(EXCLUDED.account_id, app_session.account_id)`. `NullAnalytics` is used when `ANALYTICS_ENABLED=false`. `adapters/observability/user_agent.py` does a coarse regex parse into family and device (no new dependency).
- Test doubles in `tests/fakes/`: `InMemoryUsageMeter`, `InMemoryAnalytics` (recorders); `FakeLLM` re-exported.

## 4. `POST /api/v1/events` (`api/events.py`, DTOs in `api/schemas/events.py`)
- Body `EventBatch`: `session: SessionMeta{id: UUID, viewport ≤16, app_version ≤32, entry_page ≤128, referrer_domain ≤253}`, `events: list[ClientEvent]` with `1 ≤ len ≤ 100`. `ClientEvent`: `name ≤64`, `page/prev_page ≤128`, `dwell_ms 0..86_400_000`, `properties: dict ≤ 16 keys`, `client_ts`, `seq ≥ 0`.
- Accepts `application/json` **and `text/plain`** containing JSON, because `sendBeacon` cannot set headers and a JSON blob triggers CORS. The session comes from the body, not `X-Session-Id`. Body limit is 64 KB (413 above). Auth is optional; until M1 `account_id` comes from `RequestContext`.
- Each event is checked against the catalogue. Valid events are enriched (`id`, server `ts`, `account_id`) and `track`ed. One `touch_session` per batch, with UA family and device parsed from `User-Agent`. **Response 202** `{accepted: int, rejected: [{index, reason}]}`. Unknown names are rejected per event, not per batch. A schema error or more than 100 events gives 422 problem+json. If analytics is disabled the endpoint still returns 202 and drops everything.
- OpenAPI summary and description. The handler does no awaits besides parsing the body.

## 5. Persistence: migration `0002_observability`
- `app_session` (not partitioned): `id uuid pk`, `account_id uuid null`, `started_at`, `last_seen_at timestamptz`, `user_agent_family`, `device_type`, `viewport`, `app_version`, `entry_page`, `referrer_domain text`, `created_at`, `updated_at`. Index `(account_id, started_at)`.
- `analytics_event`, `llm_call`, `external_call`: `PARTITION BY RANGE (ts)`, **`PRIMARY KEY (id, ts)`** (a partitioned table's PK must contain the partition key), columns as in §2 records + `created_at`. `cost_usd numeric(12,8)`. No FKs to `account` (account deletion is handled in M6). Indexes on the parent: event `(session_id, ts)`, `(name, ts)`, `(account_id, ts)`. llm_call `(ts)`, `(run_id)`, `(account_id, ts)`. external_call `(service, ts)`, `(run_id)`.
- Each partitioned table gets a `<t>_default DEFAULT` partition. Function `public.scout_ensure_month_partition(parent regclass, month date) RETURNS void` (plpgsql, idempotent). Partitions are named `<t>_yYYYYmMM`. In one transaction it creates `(LIKE parent INCLUDING DEFAULTS)`, moves the month's rows out of the default partition with `WITH m AS (DELETE … RETURNING *) INSERT … SELECT * FROM m`, then `ATTACH PARTITION`. Without the move, ATTACH fails when the default partition holds rows for that range. The migration calls it for previous month .. +2 for all 3 tables. Downgrade drops views, schema, tables and function.
- Schema `analytics` with `CREATE OR REPLACE VIEW`s. Every view resolves the account as `coalesce(e.account_id, s.account_id)`, which links anonymous pre-login events:
  `v_page_views_daily(day, page, account_id, views, sessions)`; `v_page_transitions(from_page=prev_page, to_page=page, transitions, median_dwell_ms = percentile_cont(0.5))` over `page_view` rows with `prev_page` not null; `v_session_paths(session_id, account_id, started_at, pages text[])` = `array_agg(page ORDER BY seq, client_ts, ts)`; `v_feature_usage(day, name, events, users, sessions)` excluding `page_view` and `web_vital`; `v_llm_usage_daily(day, account_id, feature, model, calls, input/output/cached/reasoning tokens, cost_usd, errors)`.
- Partition job `maintenance.ensure_partitions` (`adapters/observability/partitions.py`): runs the function for this month .. +3, then re-enqueues itself for tomorrow 00:05 UTC with `dedupe_key=<date>`. The worker enqueues it at startup (the dedupe key prevents duplicates). Worker handlers become closures from `build_handlers(c: Container)`, because the job needs `db`.

## 7. Invariants the tests assert
1. `offer`/`track`/`record_*` never raise and never await, even when the sink raises or blocks. The queue length stays ≤ capacity. `delivered + dropped + sampled_out + queued == offered` (Hypothesis over offer/flush/fail sequences).
2. `page_view` is never sampled out. Usage records are never sampled, only dropped when full, and each drop is logged.
3. `close()` delivers every queued item when the sink is healthy. Items offered after close are dropped, not lost silently (counted).
4. `PriceTable.cost` is ≥ 0, monotone in each token count, and adds nothing for reasoning on top of output. An unknown model costs 0 and logs a warning once per model.
5. `TokenUsage` rejects cached > input and reasoning > output.
6. FakeLLM is deterministic: same spec and input give the same output and the same tokens. An invalid fixture raises `LLMOutputInvalid` and a missing one raises `FakeFixtureMissing`. Exactly one record per run, carrying `ctx`'s account, session, run and feature and the spec's `prompt_version`.
7. LlmRouterAdapter emits one row per provider attempt (failed attempts included). `AgentResult.usage` is the sum over attempts. Rows are recorded before `LLMUnavailable` is raised.
8. `/events`: 101 events → 422. An unknown name or property key is rejected per index and the others are accepted. `text/plain` JSON is accepted. Disabled analytics still returns 202.
9. A row inserted for a month without a partition lands in the default partition. `ensure_partitions` moves it and attaches the month partition. Running it twice is a no-op.
10. 5 page views → `v_page_transitions` returns 4 transitions, and `v_session_paths` returns them in `seq` order (server `ts` is identical within a batch).

## 10. Risks
- llm-router keeps a temp-file SQLite ledger with `response_text` (vault-derived) until the process exits. Accepted for the MVP. BACKLOG: an upstream `store_text=False` option.
- llm-router does not report cached or reasoning tokens. `MeteringCompletion` reads them from LiteLLM's `usage`. A provider without these fields gives `NULL`, not 0.
- The default thread pool (8 on 4 vCPU) would starve other `to_thread` users, and `run_in_executor` does not copy contextvars. Use the dedicated pool and `copy_context().run`.
- OpenAI strict JSON schema needs `additionalProperties: false` and every field required. Agent output models with defaults set `strict_schema=False`.
- `trace.set_tracer_provider` works only once per process, so tests that build many apps rely on the idempotent guard.
