| 13 | 2026-10-20 | ADR-010 follow-up: how the Agents SDK and llm-router fit together | **Direct structured-output calls.** `LlmRouterAdapter` calls `LLMRouter.complete` with `json_validator` and `json_schema_response_format` of the agent's Pydantic `output_type`. | 14 | 2026-10-20 | Token capture with llm-router | `LLMRouter` is built directly with `completion_fn=MeteringCompletion()`, which wraps `litellm.completion` and reads `usage` (prompt/completion tokens, `cached_tokens`, `reasoning_tokens`) for each provider attempt. Each attempt becomes one `llm_call` row (`attempt` column). Retried invalid outputs are `invalid_output`, 429s are `rate_limited`. The router cache is off (`use_cache=False`). `cached_input_tokens` and `reasoning_tokens` are NULL when the provider does not report them | Every paid attempt is metered, including failed ones; costs and evals stay honest | architect (M0.11-12) |
| 15 | 2026-10-20 | Cost formula | `config/llm_prices.yaml` is the only cost source (the router's `Deployment.cost` is ignored). Cached tokens are part of input and reasoning tokens part of output, so cost = `(in-cached)*input + cached*cached_input + out*output` per 1M. The `reasoning` price is not added on top. Lookup is the exact model, then the part after the last `/`. Unknown models cost 0 with one warning per model. `cost_usd numeric(12,8)`, `Decimal` in Python | No double counting; free-tier deployments cost 0 | architect (M0.11-12) |
| 16 | 2026-10-20 | FakeLLM | Runtime adapter (`adapters/llm/fake_llm.py`, `LLM_FIXTURES_DIR`). Resolution order: scripted override, then `<Agent>/<sha256(canonical input)[:16]>.json`, then `<Agent>/default.json`, else `FakeFixtureMissing`. Fixtures are validated against `output_type`. Synthetic tokens = ceil(chars/4), model `fake` | Deterministic, schema-valid; a missing fixture fails loudly instead of returning invented data | architect (M0.11-12) |
| 17 | 2026-10-20 | Buffered writers | One generic `BufferedWriter` (bounded deque, 250 ms tick, flushes at `batch_size=500` or `flush_ms`). A failed batch is retried up to 3 flushes, then dropped and logged. Shutdown drains with a 5 s deadline, before `engine.dispose()`. Analytics: above 80 % full, non-`page_view` events are sampled 1 in 4; when full, events are dropped. Usage records are never sampled and only dropped (and logged) when full. Capacities: `ANALYTICS_QUEUE_MAX=20000`, `USAGE_QUEUE_MAX=10000` | Nothing on the request path waits for analytics I/O; losses are counted | architect (M0.11-12) |
| 18 | 2026-10-20 | `POST /api/v1/events` contract | The session comes from the body (`session.id` + meta), because `sendBeacon` cannot send headers. Accepts `text/plain` JSON (avoids a CORS preflight). Up to 100 events and 64 KB. Validation is per event: an unknown name or property key, or a string longer than 64 characters, is rejected by index while the other events are accepted. Returns 202 `{accepted, rejected}`. Anonymous events are linked to the account through `app_session.account_id` (`coalesce` in views). The catalogue in `scout/ports/analytics_catalogue.py` is the source of truth; a drift test compares it with `frontend/src/analytics/events.ts` | Stale clients lose only unknown events | architect (M0.11-12) |
| 19 | 2026-10-20 | Partitioning details (D13) | `analytics_event`, `llm_call` and `external_call` are partitioned by month on `ts`, with PK `(id, ts)` and a DEFAULT partition. `app_session` is not partitioned (upsert target). The plpgsql `scout_ensure_month_partition(parent, month)` is used by migration 0002 (previous month..+2) and by the daily self-rescheduling `maintenance.ensure_partitions` job (+3 months, `dedupe_key=<date>`). It moves rows out of the default partition before `ATTACH`. Extra columns beyond §7: `llm_call.attempt`, `external_call.http_status`, `external_call.trace_id`; `session_id` is `uuid` | One partition implementation; no `pg_partman`; no missing-partition outage | architect (M0.11-12) |
